# Оформление бота эмодзи без Premium и Fragment

## Что сделано

- Добавлен `src/ui.py` с единым набором обычных Unicode-эмодзи.
- Эмодзи добавлены в inline-кнопки главного меню, админки, навигации, списков и скачивания.
- Эмодзи добавлены в reply-кнопку «Главное меню» и основные тексты интерфейса.
- Inline-кнопки используют нейтральное стандартное оформление без `primary`, `success` и `danger`.
- Кнопка «🏠 Главное меню» принимает и новый текст с эмодзи, и старый текст без эмодзи.
- По умолчанию используется Unicode-режим, но добавлена опциональная поддержка `icon_custom_emoji_id` и `<tg-emoji>`.
- Бот автоматически извлекает `custom_emoji_id` из отправленного или пересланного сообщения и показывает найденные ID.

## Как включить custom emoji

Добавь в `.env` JSON-карту, например:

```dotenv
CUSTOM_EMOJI_IDS='{"profile":"6039422865189638057","white":"5310169226856644648"}'
```

Ключи берутся из `src/ui.py`: `profile`, `white`, `black`, `full`, `help`, `admin`, `back`, `download`, `network`, `lock`, `file`, `search` и другие. Перезапусти бота после изменения `.env`.

## Ограничение Telegram

В статье на Хабре показан синтаксис Bot API 9.4, но «кастомный эмодзи» — это именно Premium custom emoji, а не обычный Unicode-символ. По официальной документации Telegram поле `icon_custom_emoji_id` для кнопок доступно либо боту с дополнительным username на Fragment, либо в сообщениях, отправляемых ботом, если владелец бота имеет Telegram Premium.

Поэтому код готов попробовать реальные ID из твоих сообщений, но сервер Telegram может вернуть ошибку прав. Никакого обхода ограничения в коде нет. Если Telegram отклонит ID, нужно будет использовать Premium/Fragment или вернуться к Unicode-режиму.
